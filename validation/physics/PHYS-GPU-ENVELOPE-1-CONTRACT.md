# GPU upper-envelope atlas contract

The base physical surface is the highest world Y of LONG + MID + SHORT, including the authoritative Coastal warp, confidence and one-cell feather. BreakerCarrier is excluded. Water occupies the region below the selected surface. Contact Y determines signed depth only.

Historical modes 0–4 and their shader remain available. New mode **5, PHYSICAL_ENVELOPE_ATLAS**, has a separate opt-in wrapper and persistent state. Its raster and compute stages obtain surface sampling, derivatives and FP64 bounded refinement verbatim from the frozen `ocean_surface_query.glsl` source. The stage compiler checks both source delimiters and shader compiler diagnostics. It does not author a second ocean transform.

Resources are created once per configured lifetime: dedicated normalized regular q grid, index/vertex arrays, RGBA32F color attachment, D32_SFLOAT depth attachment, framebuffer/pipeline, tile state, GPU extrema and uniform sets. No visual ocean clipmap topology or camera state is consumed. The initial proof uses one 16 m × 16 m world tile; resolution and q-grid density are configurable. The class reserves a fixed capacity at initialization and does not resize during a tick.

The q patch expands by GPU-computed current horizontal displacement bounds on each axis. A reduction scans authoritative displacement texture extrema, Coastal shoaling/confidence and warp confidence. Bilinear sampling is convex; the bound accounts for the sum of bands, long-field mixing, shoaling, horizontal/vertical scales and FP32 slack. The prior Hs-derived visual bound is statistical and is not used as this conservative bound. No CPU texture readback participates.

Depth clears to **0** and uses **GREATER_OR_EQUAL** with depth writes. Each draw maps displacement Y from `[-(bound.y+1), +(bound.y+1)]` into `[0,1]`; sea level is added to the recorded surface Y. Higher Y therefore wins. The runtime bound defines both supported range and clipping plane; a surface outside this conservative range would invalidate the bound contract. Per-instance fragment clipping prevents overscan geometry from writing a neighboring atlas cell.

Each atlas pixel stores `(q.x, q.z, world_surface_y, valid)` in 16 bytes. It is a sheet selector and seed, not final height authority. Compute uses `texelFetch` on the nearest member of a 2×2 neighborhood and never interpolates q across texels. A neighborhood with holes, q discontinuity or significant Y discontinuity refines up to four stored seeds; an owned previous q may be a fifth candidate for the 2 mm Y hysteresis. Each solve is capped at 16 iterations, with the existing 1 mm world residual gate and FP64 evaluation. No heuristic seeds, rings, historical recovery or CPU q feedback are invoked.

Final displacement, velocity, normal, world position and signed depth are evaluated from the authoritative fields at refined q. Selection chooses the greatest candidate Y, with a 2 mm tie band. An owned previous candidate is eligible only within ±2 mm of the atlas-derived maximum; it cannot introduce a separate higher sheet or remain more than 2 mm below that maximum. Continuity distance classifies status after selection and cannot validate a surface. Failed/empty atlas acquisition cannot be rescued solely by previous q.

GPU order is authoritative FFT updates → extrema reduction → rasterization → optional validation-only hole count → exact query → asynchronous output-buffer readback, all on the same global RD. Tile state stamps query generation, configuration, ocean epoch and exact FP32 sample time. It travels with the coalesced packet. Tile vehicle identity and occupant generation are checked against each contact's tile assignment; the expected tile generation uses the formerly unused control offset 24 as a u32 bit payload, independently of contact-slot generation. The atlas is consumed before any subsequent field update. Production uses no `rd.sync()`, blocking `buffer_get_data()` or atlas readback. The three-slot readback ring and coalesced lifetime invalidations remain shared with the historical wrapper.

New output strides are **208 bytes rich / 176 bytes compact**. The first 160 / 128 bytes preserve the physical contact layout. Three additional vec4 words record nearest atlas q/Y/valid, conservative displacement bound plus validation hole count, and tile/query generation, valid-neighbor count and tile occupant generation. GPU hole count is an integer bit payload. These diagnostics are final output-buffer data; no CPU atlas texture is read.

The validation runner reuses committed PHYS-GPU-1.3 oracle roots. Reference completeness remains bounded, as documented in that phase; new correctness claims cover only tested archived targets. A reproducible valid result more than 2 mm below reference upper Y disqualifies the tested configuration. A configuration is not selected merely because a small smoke subset passes.

Phase B failed the zero-wrong-sheet gate. Initialization therefore accepts only one tile; multi-vehicle capacity and its performance validation remain gated. This opt-in proof is not approved for physical force use.
