# PHYS-TARGET-READY

Reproducible Windows build and validation entry points for a clean checkout. This
prepares the i7-13650HX / RTX 4070 Laptop run; it does not claim that hardware has
already been measured.

## Clean-clone commands

Install Git, Python 3, Visual Studio 2022 Build Tools with the x64 C++ tools and a
Windows 10/11 SDK, and Godot 4.7.1. The scripts do not install Python or Visual
Studio. SCons 4.11.1 is installed with the selected Python only if it is missing.

From the repository root:

```powershell
.
validation\physics\setup_native_windows.ps1 -GodotExe 'C:\path\to\Godot_v4.7.1-stable_win64_console.exe'
.
validation\physics\run_target_validation.ps1 -GodotExe 'C:\path\to\Godot_v4.7.1-stable_win64_console.exe'
```

The first command clones `godot-cpp` tag `10.0.0-stable`, verifies commit
`507ed9d840c01a3c5b2a39af8bb4000bfac30bf5`, initializes the VS 2022 x64 developer
environment, builds `template_release`, and verifies the generated DLL/descriptor.
It leaves the dependency checkout ignored and local. The second command reruns the
build, checks class registration and instantiation, runs the PHYS-3 correctness
runner, native scalar/batch benchmarks, Ocean matrix, and B0/B1/B2 breaker matrix.
Logs and JSON summaries go under the selected output directory (default: a new
folder in `%TEMP%`). It hashes `project.godot` before/after to verify settings were
not changed.

Use `-SmokeOnly` to run build and native-load checks only, or `-SkipBuild` when
reusing a locally built DLL. The clean-checkout rehearsal uses `-SmokeOnly`; the
full laptop validation command above uses neither switch.

## Frozen benchmark setup

| Item | Ocean feature matrix | Breaker B0/B1/B2 |
|---|---|---|
| Scene | Generated by `validation/ocean_benchmark.tscn` script | `validation/p0_open_ocean.tscn` |
| Camera | `(0, 8, 16)`, rotation `(-12, 0, 0)` degrees | `FreeCamera` from scene, fixed after startup; transform printed in `TARGET_BREAKER_ENV` |
| Output size | 1920×1080 requested and set at runtime | 1920×1080; runner fails if viewport differs |
| Renderer | Forward+ / D3D12 from `project.godot` | Same |
| VSync / FPS cap | VSync off; uncapped (`Engine.max_fps=0`) | VSync off; uncapped |
| Debug / release | Godot 4.7.1 official console executable; runtime debug status logged. OceanQueryNative is `template_release` | Same |
| Dynamic resolution / upscaling | Off | Off |
| FFT / Coastal | Full LONG+MID+SHORT matrix; Coastal state per named matrix row, never camera-distance physics | P0 scene configuration held fixed; full FFT and Coastal remain active |
| Breakers | Explicitly off for every Ocean feature-matrix state | B0 off; B1 lifecycle active with surface breaker route disabled; B2 normal route |
| Other effects | Named matrix rows control optics, SSPR, surface detail, foam, underwater effects, and environment; seed 20260820, Hs 2.574 m, wind 18 m/s at 5.71°, swell 0.80, scales 1.0 | P0 scene's authored optics/Coastal/foam/environment configuration |
| Warm-up / samples | 3 s / 5 s per matrix case | 5 s / 10 s per repeat; 3 repeats per B0/B1/B2 state |

Ocean matrix logs mean/p95 frame, CPU, GPU, FPS, and named feature state. Breaker
results include B1-B0, B2-B1, and B2-B0 deltas. PHYS native workloads cover 1, 4,
16, 64, and 256 queries for LONG, LONG+MID, all three bands, and all three bands
plus Coastal, with scalar and batch paths. Results identify the actual CPU/GPU.
Historical FPS is not comparable unless these conditions match.

## Repository contents versus local files

### Required in Git

- Production PHYS adapters/snapshots and TIME-1 source already tracked in the
  repository, including `phys1_spectrum_adapter.gd` and the Ocean/FFT changes.
- Native source, SConstruct, release batch helper, and tracked
  `ocean_query_native.gdextension.template`.
- PHYS-1/2/3 probes and Coastal parity reports already tracked.
- `setup_native_windows.ps1`, `run_target_validation.ps1`, native load and
  benchmark scripts, Ocean benchmark metrics, scoped ignore rules, and this guide.

### Downloaded third party

- `addons/ocean/physics/native/godot-cpp/`: exact pinned upstream checkout above;
  ignored by Git and excluded from Godot scanning with `.gdignore`.

### Generated locally

- `ocean_query/build/`, `ocean_query/bin/`, active
  `ocean_query_native.gdextension`, DLL/OBJ/PDB/LIB/EXP files, SCons signature,
  Godot generated validation script UIDs, and transient shader import sidecars.
- Benchmark output/log/summary files in `%TEMP%` or the Godot `user://` folder.

### Local cache

- `.godot/` and `.codebase-memory/`; they are ignored and should not be deleted as
  part of validation.
- Python/SCons packages and Visual Studio/Windows SDK installations remain machine
  local and are not repository files.

Consequently the many files under `godot-cpp/include`, `src`, and `gen` are a
downloaded local dependency, not Ocean-Production repository content.

## Rehearsal and limitations

The clean-clone rehearsal uses a fresh Git worktree of the target commit. The
bootstrap downloads the pinned dependency into that worktree, then builds and loads
the extension without copying a DLL, dependency checkout, generated binding, cache,
or benchmark output from the GTX 970 machine. A real RTX 4070 Laptop run is still
required before accepting target-hardware performance.

Rehearsal on 2026-09-30 passed from a fresh temporary worktree: pin verification,
MSVC x64/SDK detection, full first build, descriptor checks, Godot import, class
registration, and instance creation. The first clean build took 249.39 s on the
i7-5820K; subsequent build verification was incremental.

The old-PC short Ocean smoke (`0.25 s` warm-up / `0.75 s` sample) emitted D3D12
shader-cache warnings and invalid-RID errors while rapidly switching crest/surface
foam matrix states. Those smoke timings are not valid benchmark results. The full
runner preserves each Godot log and records error lines in its JSON summary so this
can be checked again with the normal 3 s / 5 s measurement on the target laptop;
no Production renderer or Coastal behavior was changed here.
The runner also restores only tracked `.import` sidecars that were clean before its
Godot import step; any pre-existing user changes are left untouched.
